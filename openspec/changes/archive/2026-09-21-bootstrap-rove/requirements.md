# Rove 详细需求说明

## 1. 产品定位与使用者

Rove（漫游者）帮助个人统一使用自己的多种设备、网络和自托管服务。用户安装 Rove、创建或加入网络后，即可选择一台设备，通过该设备上的 `rove-agent` 对话并执行装配任务，再从同网络其他设备使用发布出来的服务。

目标设备包括 Linux、Windows、macOS 电脑与无界面主机，以及 Android/iOS 手机、平板。每台设备具有相同的逻辑 agent，能力取决于设备平台和已安装软件。AI 运行指编排和工具执行发生在目标设备，模型推理可由该设备配置的云端或本地模型接口提供。

使用者包括希望低门槛安装和使用服务的个人、需要远程管理开发设备的开发者，以及获得网络配置的可信朋友。它们是用户场景分类，不是系统角色或权限等级。网络成员均被信任；Rove 不增加账号、角色、审批或中心控制器。

## 2. 范围与边界

| 范围 | 首版行为 |
| --- | --- |
| 桌面与无界面设备 | 完整组网、AI、服务发布、远程操作闭环 |
| 手机与平板 | 同一核心和 GUI 接入、扫码入口及明确的平台能力反馈；native 网络和后台集成后续交付 |
| 网络 | 个人可管理和分享多个网络；每台设备同时只加入一个网络，地址交由 EasyTier DHCP |
| AI | 每设备配置、会话与执行；不同会话并发；通用工具装配 |
| 服务 | 本机服务的 TCP 代理、地址和应用认证信息登记 |
| 交互 | GUI 与 CLI 业务功能对等；相机等设备动作提供等价参数输入 |
| 暂缓 | 通用账户数据同步、插件市场、跨设备 AI 自动编排、移动 native 扩展、UDP 和统一域名/TLS 管理 |

“个人”不意味着需要 Rove 登录账号；用户在本机保存网络和设备配置。“对等”不意味着全部设备有相同系统能力，也不意味着离线设备上的作业可以自动搬到其他设备执行。

## 3. 业务名词与归属

| 对象 | 含义与拥有者 |
| --- | --- |
| Device | 一个保留本地数据的 Rove 安装，持有稳定 `device_id` |
| Network | 可分享的个人 overlay 网络，持有跨设备稳定 `network_id` |
| Network instance | 某设备本机运行该网络的实例，由 EasyTier 适配器管理 |
| Session | 目标设备保存的一段 AI 对话上下文 |
| Run | 一次消息触发的 AI 执行，具有独立状态、取消与输出 |
| Service | 提供设备上的持久发布定义及当前代理入口 |
| Join config | 入网必需参数与网络 ID，不包含设备私有数据 |
| Share blob | 公网保存的有时限密文，没有设备列表或执行能力 |

个人可保存多个网络配置；一个设备同时只加入一个网络，一个网络可有多个设备。会话与模型配置属于设备，服务关联提供设备与发布网络。加入配置传播网络身份，不能传播分享者的设备身份。本机账号的文件权限决定命令实际可操作范围。

## 4. 功能需求

### FR-01 安装、初始化与后台运行

- 桌面包包含 GUI、`rove` CLI、agent 和配套网络程序；无界面包包含 CLI、agent 和网络程序。
- 首次初始化生成稳定 UUID 设备身份和本机数据目录；保留数据的更新不得生成新身份。
- 同一数据目录只能有一个活动 agent；多个 GUI/CLI 接入同一实例。
- 桌面关闭界面不终止已接受作业、网络或代理；停止后台服务必须是显式操作。
- 移动平台进程可能被系统暂停或终止，界面需准确展示能力边界，不能把该平台描述成仅可被控制的从属节点。

### FR-02 多网络生命周期

- 用户可创建、查看、显式修改、启动、停止和删除本机网络记录。
- 创建和导入只保存配置；启动加入网络，停止退出。切换前必须停止当前网络；并发启动也不得产生两个活动实例。未确认退出的失败实例仍占用加入资格。
- 地址由原版 EasyTier DHCP 管理，不要求不同网络地址段互斥，不维护 Rove 地址分配器或 EasyTier 补丁。
- 创建时生成 `network_id`；入网时保留已有网络 ID并使用自己的本机实例标识。
- 网络列表分别展示期望状态、实际状态和错误，某网络故障不得删除另一网络配置。
- 停止网络保留配置并关闭对应入口，不取消已接受的本机 AI 作业，也不卸载目标应用。
- 删除前需要网络处于停止状态；这是避免连接和配置半更新的状态条件，不是权限审批。

### FR-03 扫码、URL 与手动加入

- 三种交互最终得到同一版本化加入配置。二维码编码分享 URL。
- 分享端生成新随机密钥，本机认证加密配置后上传，解密密钥进入 URL fragment。
- 配置服务只获得密文及时间、大小等元数据；普通日志不得保存完整分享 URL 或解密密钥。
- 默认七天有效且可重复使用；过期只阻止后续下载，不撤销已加入设备。
- 错误密钥、篡改、不支持格式和下载失败都必须返回明确错误，不保存部分配置。
- 手动录入网络 ID、显示名和底层入网参数，不依赖配置托管服务。
- 相同 ID 相同配置重复导入返回已有网络；不同配置同 ID 必须显式更新，不静默覆盖。

### FR-04 发现与选择设备

- 根据每个网络当前 peer 候选识别 Rove 设备，按 `device_id` 合并设备记录。
- 列表显示名称、平台、在线状态、当前访问地址与能力；普通 EasyTier 节点不被视为可执行 agent。
- `peer_id` 与 IP 变化只刷新路由，不创建新的业务设备。
- 用户选择的网络与设备在 GUI/CLI 中持续可见；不可达时不得改成在本机执行。
- 首版按需刷新和缓存足够，不引入中心设备注册表。

### FR-05 模型配置

- 每设备保存一个默认配置，包含提供方、接口地址、模型及可选 API key，支持可信远端设置。
- 获取配置默认只返回是否配置密钥，不返回密钥本身；这不承诺对已获设备执行能力的成员隐藏本机文件。
- 运行开始时快照模型配置；修改只影响后续开始的作业。
- 未配置模型仍能管理网络与服务，但提交 AI 请求须报告需要配置模型。

### FR-06 会话、作业与并发

- 在目标设备创建、列出和读取会话；后续客户端可继续同一会话。
- 同会话作业按接受顺序执行；队列中的未来消息不得提前进入当前 run 的模型上下文。
- 不同会话默认最多四个 run 同时运行；可配置正整数上限。
- 超过并发上限进入可见队列；同会话等待项不得占用运行槽阻塞其他会话。
- 调低上限不取消运行中的作业。队列资源耗尽需明确报错，不无限接受。
- 单 run 的工具调用顺序执行，跨 run 的命令可并发；包管理器锁、文件和端口竞争作为实际工具结果返回。

### FR-07 断线、重试与取消

- 接受作业后，目标保存 `request_id` 与 `run_id`。同一请求重试返回同一作业；同 ID 不同内容返回冲突。
- 每个 run 可查询状态、输出和有序事件；客户端通过事件序号恢复订阅。
- 断线不等于取消，取消必须指定 run；取消一个 run 不影响其他会话。
- 已完成的命令副作用不因取消而回滚；无法停止的进程必须如实报告。
- agent 重启把旧的 queued/running/cancelling 作业归为 `interrupted`，不自动重新执行；新作业需新请求。

### FR-08 通用 AI 装配

- `system_exec` 提供本机命令执行，`publish_service` 提供服务发布；安装方式由 AI 根据实际设备确定。
- 用户可要求装配 coding 工具、养成类 agent 或音乐服务器；这些是可验证示例，不是预设业务操作接口。
- 命令以 agent 所在 OS 账号执行，结果含输出与退出状态；需要系统提权时通过 OS 机制处理或明确失败。
- 对不支持的平台能力直接返回 `unsupported`，允许后续通过 native 插件扩展。

### FR-09 发布与使用服务

- 发布创建 overlay 地址端口到本机回环端口的 TCP 代理并登记服务。
- 成功必须同时满足代理建立和定义保存；失败不能产生虚假可用记录。
- 目录按所选网络展示，数据保存在提供设备；浏览器服务给出 HTTP/HTTPS URL及应用认证信息。
- 设备重启和网络恢复后重建代理；地址变化更新当前 URL。第三方应用持有旧地址时可能需重新配置。
- 更新已发布目标或端口时，失败应保留旧的可用发布；无法安全更新则先返回冲突。
- 取消发布关闭入口、删除发布定义，不停止或卸载原应用。

### FR-10 GUI 与 CLI 对等

- GUI 每个业务动作具有同等 CLI 操作；相机扫码对应 URL 输入，打开浏览器对应输出地址。
- CLI 提供交互入口、帮助、子命令、结构化输出及可靠退出码。
- GUI/CLI 都使用 SDK；两者不独立修改 agent 数据库或网络底层配置。
- 模型错误、排队、取消中、离线、不兼容和平台不支持必须有可区分展示。

### FR-11 机器可读接口契约

- Agent HTTP API 与配置服务 API以 OpenAPI 3.1 定义路径、operationId、参数、请求、响应、错误及数据模型。
- 本机 socket 以 OpenAPI 的 operationId 和 schema 为业务契约，额外定义帧、目标转发和订阅控制。
- 流式接口明确 SSE 数据帧与序号恢复方式；不能用一个泛化 JSON 对象替代所有业务 schema。
- 契约变更同步 SDK、实现和测试；兼容性破坏必须变更协议主版本。

## 5. 质量与非功能要求

| ID | 要求 | 验证方式 |
| --- | --- | --- |
| NFR-01 易用性 | 未配置 AI 也能完成加入网络；GUI与 CLI 错误带可采取的下一步 | 从干净安装执行入网流程 |
| NFR-02 一致性 | 设备、会话、服务有稳定身份；接受记录与去重信息同事务保存 | 丢响应、重启、地址变化测试 |
| NFR-03 并发 | 默认四个不同 session 可同时运行，第五个排队 | 可控执行器屏障测试，不靠计时猜测 |
| NFR-04 有界资源 | 输入、帧、输出与队列有明确上限，超限可见 | 边界值、慢客户端和超限测试 |
| NFR-05 运行独立性 | 桌面/无界面 agent 不依赖 GUI 和配置服务在线 | 关闭 GUI、停止配置服务再查询作业 |
| NFR-06 网络边界 | 无二次 Rove 权限层；执行入口仅供本机账号及 overlay 成员访问 | overlay 正向测试与物理网负向测试 |
| NFR-07 可移植性 | 能力按平台报告，发布架构必须有验证记录 | Linux/Windows/macOS及移动壳矩阵 |
| NFR-08 可诊断性 | 错误码稳定、消息可读、事件归属明确；已执行步骤不被失败覆盖 | 工具失败及部分完成测试 |
| NFR-09 契约完整性 | OpenAPI 可解析、引用可解析、operationId 唯一、schema 与示例可验证 | OpenAPI校验与契约一致性检查 |

不预先承诺无测量依据的启动秒数、模型响应时间、网络吞吐和在线 SLA；实际平台验收记录这些指标，再确定性能目标。

## 6. 追踪与首版验收

| 需求 | 用户故事 | 能力规格 | API 范围 |
| --- | --- | --- | --- |
| FR-01 | US-01、US-12、US-15 | device-runtime | hello、device、settings；安装生命周期由 CLI/OS 完成 |
| FR-02 | US-01、US-04 | overlay-network | networks、start/stop、join-config |
| FR-03 | US-02、US-03、US-13 | network-sharing | imports、shares、配置服务 blobs |
| FR-04 | US-04、US-05 | overlay-network、agent-communication | network devices、hello |
| FR-05 | US-05 | ai-sessions | model-config |
| FR-06 | US-06、US-07 | ai-sessions | sessions、runs、settings |
| FR-07 | US-08、US-09、US-14 | ai-sessions、agent-communication | run、events、cancel |
| FR-08 | US-06、US-10、US-15 | ai-sessions | submit_run；通用工具 schema |
| FR-09 | US-10、US-11 | service-publishing | services |
| FR-10 | US-12 | user-interfaces | 同一 agent operationId 全集 |
| FR-11 | US-16 | agent-communication | 两份 OpenAPI + 本机 socket 映射 |

首版闭环：在 A 创建网络，B 用 URL 加入；A 选择 B 配置模型，向 B 提交装配请求；B 通过通用工具启动本机服务并发布；A 取得服务地址与应用凭据并访问。随后用另一客户端继续原会话，验证并发、取消、断线和重启结果符合上述要求。
