# Rove 用户故事与验收

故事中的个人、开发者和朋友只描述使用动机，不引入账号或权限角色。所有设备均为对等设备；“目标”只表示本次选中的执行设备。

## US-01 创建我的个人网络

作为个人用户，我希望安装后创建一个网络，让电脑成为以后其他设备的加入入口。

- 前置：完成桌面或无界面安装，本机 agent 可连接。
- 主流程：打开 GUI 或 `rove` → 输入网络名称 → 创建网络 → 启动 → 查看本机设备和实际状态。
- 验收：生成稳定网络 ID与设备 ID；未配置 AI 也能完成；GUI 关闭后网络仍运行。
- 异常：网络权限不足或底层启动失败时保留配置并显示失败原因，不显示假在线。
- 对应：FR-01、FR-02；`create_network`、`start_network`、`get_network`。

## US-02 用二维码分享给可信朋友

作为网络使用者，我希望把二维码发给朋友，让对方像我的其他设备一样加入并操作网络设备。

- 前置：已有网络，密文托管服务可达。
- 主流程：选择分享 → 获得二维码与 URL → 朋友扫描 → 本机解密并导入 → 启动网络。
- 验收：无账号注册和审批；双方网络 ID 相同、设备 ID不同；模型密钥和服务密码不进入加入包。
- 异常：上传失败不生成虚假可用链接；错误密钥和过期链接明确失败。
- 平台：扫码是产品交互；首版移动壳导入后如尚无 native 网络能力，须显示未连接，而非宣称完成组网。
- 对应：FR-03；`create_network_share`、`import_network`、`upload_blob`、`download_blob`。

## US-03 在没有图形环境的服务器加入

作为使用服务器的用户，我希望粘贴 URL 或输入参数完成加入，不依赖相机或 GUI。

- 主流程：通过 `rove` 输入 URL → 查看加入结果；公网托管不可用时改用手动配置。
- 验收：两种方式得到相同逻辑网络；自动生成本机实例；重复导入同配置返回已有网络。
- 异常：同网络 ID 不同配置返回冲突，用户显式更新后生效，不静默覆盖。
- 对应：FR-03、FR-10；`import_network`、`update_network`。

## US-04 切换和管理多个网络

作为同时管理家庭和朋友网络的用户，我希望分别查看网络及其设备，不必删除已有配置才能加入另一个。

- 主流程：保存第二个网络配置 → 查看当前加入状态 → 停止当前网络 → 启动另一个网络 → 刷新设备。
- 验收：设备同时最多加入一个网络；切换前后 device_id 不变，网络配置分别保留，个人可以分享任一已保存配置。
- 异常：未停止当前网络时启动另一网络返回 network_already_joined；实例失败独立展示，未确认清理前不启动另一网络；停止网络不卸载设备上的应用。
- 对应：FR-02、FR-04；`list_networks`、`list_network_devices`、`stop_network`。

## US-05 在电脑上给另一台设备配置模型

作为个人用户，我希望从当前界面设置目标设备的 AI，以后直接选择它执行任务。

- 主流程：选择 B → 打开模型设置 → 填写接口、模型和密钥 → 保存 → 新建会话。
- 验收：配置保存于 B，A 的配置不变；查询只显示密钥是否配置；后续 B 的 run 使用 B 的设置。
- 异常：B 离线则明确不可达；没有模型时提交失败且不执行命令。
- 对应：FR-04、FR-05；`get_model_config`、`set_model_config`、`create_session`。

## US-06 让 AI 装配开发工具

作为开发者，我希望告诉目标设备安装并配置一个 coding 工具，让 AI 根据该设备实际环境处理。

- 主流程：选择目标 → 创建会话 → 描述所需软件 → 查看工具输出与最终结果。
- 验收：只有所选设备执行；软件名称不会变成必须预置的 API；输出与失败步骤可追踪。
- 异常：缺少系统权限、网络下载失败、命令不可用都成为可读工具结果；不假称安装成功。
- 对应：FR-06、FR-08；`submit_run`、`subscribe_run_events`、`get_run`。

## US-07 同时推进多个任务

作为使用多个会话的用户，我希望一边安装软件，一边让另一个会话处理别的工作。

- 主流程：创建会话 A 和 B并各发消息；继续在 A 发第二条消息；再提交其他独立会话。
- 验收：A1 与 B1 可并行；A2 等待 A1 且不占设备运行槽；默认四个独立 run 可运行，第五个排队。
- 异常：调低并发上限不取消已有 run；共享资源冲突显示实际错误，不让所有命令全局串行。
- 对应：FR-06；`update_settings`、`submit_run`、`list_runs`。

## US-08 换设备继续看执行结果

作为漫游用户，我希望提交任务后关闭当前界面，再从另一设备查看进度与继续会话。

- 主流程：A 向 B 提交任务 → 关闭 A 界面 → C 连接 B → 查看原会话和作业 → 恢复事件订阅。
- 验收：B 继续执行；C 获得同一 run 和已保存输出；事件不重排，重连不重新提交任务。
- 异常：B 离线时显示不可达，任务不会自动在 C 重新执行。
- 对应：FR-07；`list_sessions`、`list_messages`、`get_run`、`subscribe_run_events`。

## US-09 只取消一个任务

作为同时运行多任务的用户，我希望取消选错的任务，而其他任务继续。

- 主流程：在作业列表选择一个 run → 取消 → 查看取消中及最终状态。
- 验收：排队任务直接取消；运行任务停止后续工具并尝试终止受管理进程；其他 run 继续。
- 异常：取消前已完成的安装不回滚；未能停止的子进程显示残留信息，不能宣称系统已恢复原状。
- 对应：FR-07；`cancel_run`、`get_run`。

## US-10 装配并发布音乐服务

作为喜欢音乐的用户，我希望让设备 B 安装音乐服务，再从设备 A 的浏览器或音乐应用使用。

- 主流程：向 B 描述需求 → AI 执行安装和启动 → 发布回环端口 → A 查询服务卡片与应用凭据 → 打开。
- 验收：实际 TCP 代理可连通；服务定义属于 B并关联所选网络；Rove 不另加应用登录。
- 异常：目标没启动、端口不可绑定或应用自身认证失败时显示真实结果，不能只登记 URL 当作部署成功。
- 对应：FR-08、FR-09；`submit_run`、`publish_service`、`list_services`、`get_service`。

## US-11 停止对外发布但保留应用

作为服务使用者，我希望取消入口而保留已经部署的软件和数据。

- 主流程：选择服务 → 取消发布 → 再查询列表。
- 验收：入口不再接受新连接，发布定义被删除；目标进程、数据和会话历史不被移除。
- 异常：提供设备不可达时报告操作未确认，不在本机删除卡片后声称远端已取消。
- 对应：FR-09；`unpublish_service`。

## US-12 GUI 与 CLI 切换使用

作为既用桌面也用终端的用户，我希望两种入口提供相同业务能力和同一份状态。

- 主流程：GUI 创建网络和会话 → CLI 查询并继续 → GUI 查看新输出。
- 验收：目标、会话和 run 身份一致；CLI 支持结构化输出，诊断不混入 JSON；无 TTY 缺参数明确失败。
- 异常：第二个本机 agent 不得成为同一数据目录的另一个写入者。
- 对应：FR-01、FR-10；全部 agent operationId。

## US-13 理解分享链接到期

作为分享者，我希望知道为什么新设备无法导入，也希望已经加入的设备继续工作。

- 主流程：使用七天前的链接导入 → 看到过期或不可用 → 在已加入设备重新分享。
- 验收：已加入设备不退出网络；未过期链接允许重复导入；新分享使用新密钥与新 blob。
- 对应：FR-03；`download_blob`、`create_network_share`。

## US-14 设备重启后判断任务状态

作为用户，我希望重启后能知道之前做到了哪里，避免旧命令突然再次执行。

- 主流程：执行期间重启 B → 连接 B → 查看会话和服务。
- 验收：旧未完成 run 均显示 `interrupted`，已写入输出保留；持久服务代理尝试恢复，失败单独显示。
- 异常：重试同一 request_id 返回原中断 run；想重新执行需明确创建新请求。
- 对应：FR-07、FR-09；`get_run`、`submit_run`、`list_services`。

## US-15 理解移动设备能力差异

作为平板用户，我希望使用熟悉的 Rove 界面，并知道哪些操作当前平台能做。

- 主流程：打开应用 → 查看设备能力 → 尝试尚未实现的本机操作。
- 验收：同一逻辑 agent 回答 `unsupported`，不使用控制端/工作端角色限制；已实现功能仍可使用。
- 边界：native VPN和后台常驻属于后续交付，首版移动壳不作为完整两设备网络验收的替代。
- 对应：FR-01、FR-08；`get_hello`、`get_device`及作业工具结果。

## US-16 按契约开发客户端

作为 SDK 或 GUI 开发者，我希望从 OpenAPI 得到完整类型和错误语义，并复用本机/远端 API。

- 主流程：读取 OpenAPI → 按 operationId 实现 SDK方法 → 验证请求与响应 schema → 在 socket 与 HTTP 上执行同一契约测试。
- 验收：引用可解析、operationId 唯一、SSE 事件类型可验证、socket 请求映射不依赖独立业务协议副本。
- 异常：不兼容版本明确拒绝；重复 request_id 不创建第二份作业。
- 对应：FR-11；两份 OpenAPI及 local-socket.md。
