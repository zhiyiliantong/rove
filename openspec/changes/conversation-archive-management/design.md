## Context

动机参见 proposal.md。当前独立原型通过 `PrototypeApi` 进程内 mock 适配器和 localStorage 保存数据，`Snapshot.version` 为 3，`Session` 尚无归档字段。`ChatPage.vue` 直接遍历全部会话；任务通过 `session_id` 关联消息并推进模拟回复，因此不能只删会话而留下任务。现有 OpenAPI 0.5.0 明确没有 HTTP 服务实现。

## Goals / Non-Goals

**Goals:**

- 在同一会话身份上实现可恢复归档，确保任务关联、旧数据与移动布局兼容。
- 数据层和界面同时保护删除与归档后的只读行为，避免仅靠隐藏按钮保证正确性。

**Non-Goals:**

- 不增加独立进程、远程同步、真实文件删除、自动清理或批量操作。
- 不实现搜索、文件夹、置顶及保留期限；不重构正式 agent 数据模型。

## Decisions

### 1. 状态字段，不搬移会话集合

为 `Session` 增加 `archived_at: number | null`，使用 Unix 毫秒时间戳；null 表示正常会话。快照仍使用单一 sessions 集合，界面分别过滤日常和归档记录。归档记录按归档时间倒序，恢复后沿用原集合顺序，不伪造新会话时间。

备选为独立 archived_sessions 集合，但会增加任务查找、迁移与恢复重复标识的风险。时间字段同时支持排序，无需额外 archived 布尔值。重复归档保持原时间，恢复已正常会话为无副作用操作。

### 2. 入口和路由

- 会话列表项使用独立“更多”按钮菜单，不能在现有整个按钮内嵌套按钮；详情标题区也提供“归档会话”。
- 会话区提供“归档管理”入口，设置页增加相同入口；不新增第四个主导航标签。
- 使用独立 `/archives` 页面，路由匹配在通用会话详情之前处理；保持现有桌面侧栏和移动底栏。
- 归档管理每条显示标题、归档时间和活跃任务提示，提供查看、恢复、删除。查看使用原 `/sessions/{id}` 链接，以只读归档状态显示，保留消息复制、朗读和任务进度，隐藏发送及配置修改，提供恢复。
- 删除确认明确“永久删除会话及任务历史，不会删除已部署服务”，默认焦点放取消，键盘关闭等同取消；沿用已有确认交互或相同 PrimeVue 主题组件，不引入依赖。

备选是仅在设置里提供入口，发现成本较高；直接在常规列表提供永久删除容易误触，本次仅归档管理中提供。

### 3. 任务与删除约束

归档不修改 runs。mock 的推进仍遍历所有会话的任务，归档详情可以观察进度。归档会话的 submit、saveDraft、setSessionModel 和 setSessionTarget 须在适配器层拒绝；任务本身产生的消息更新不受只读限制。

删除适配器在执行时重新检查：会话存在、已经归档、所有关联任务均处于终态。queued/running/cancelling 均阻止删除，不能只信任界面检查。通过检查后一次更新内删除该 session 及关联 runs，再保存快照；不触碰服务等集合。不存在会话按缺失记录处理，删除未归档会话或有活跃任务会话按冲突处理。

备选为删除时自动取消或分离任务，但会改变用户请求语义并扩大任务生命周期范围，因此暂不采用。需取消任务时先恢复会话，使用已有取消入口。

### 4. OpenAPI 与模块契约

实现前扩展 `apps/rove-prototype/api/prototype.openapi.json` 为 0.6.0。它仍仅是原型接口定义，不启动 HTTP 服务；快照用于读取两个列表，无需重复新增列表接口。

| OpenAPI 路径 | 方法 / operationId | 进程内对应方法 | 响应 |
| --- | --- | --- | --- |
| `/sessions/{id}/archive` | POST / archiveSession | `archiveSession(id): void` | 204；404 会话不存在 |
| `/sessions/{id}/archive` | DELETE / restoreSession | `restoreSession(id): void` | 204；404 会话不存在 |
| `/sessions/{id}` | DELETE / deleteSession | `deleteSession(id): void` | 204；404 不存在；409 未归档或有活跃任务 |

三个操作均只需必填字符串路径参数 id，无请求体。定义或复用错误 schema，错误须包含明确消息及可辨识原因；在草稿、模型、执行目标和提交任务的已有操作中声明归档状态 409 冲突。更新 Session required 字段和快照 version schema，验证成功/失败样例与 mock 返回语义一致。

### 5. 兼容迁移

Snapshot 升至 version 4，继续使用现有存储键。加载 version 1/2/3 时保留既有迁移，再补充所有 session.archived_at = null；旧数据不能被空白场景覆盖。新会话和演示种子默认 null。维持 initialized 标志，不能因为初始化会话被归档或删除而重新触发引导。

## Risks / Trade-offs

- [用户误认为归档停止任务] → 操作反馈说明归档仅整理列表，归档管理显示进行中任务。
- [删除引发任务推进引用悬空] → 数据层重检并只删除终态任务和对应会话，测试取消中与排队状态。
- [旧路由或模型删除后归档详情渲染失败] → 保留现有缺失模型降级，未知会话显示返回入口；测试旧链接。
- [移动端更多按钮挤压长标题] → 独立可聚焦按钮、标题截断与响应式排列，检查 390px 及桌面尺寸。
- [浏览器存储不可用] → 沿用当前原型仅内存降级，不宣称刷新后一定保存；真实 agent 持久化仍不在范围。

## Migration Plan

1. 待用户审核提案后，先更新原型契约、数据迁移及单元测试，再接入页面与浏览器测试。
2. 构建通过后更新同一 4173 原型预览，保留现有网络监听范围；更新 README 与交接文档，将本次功能标为待验收，不更改 0.5 历史验收。
3. 回退必须保留用户快照，不使用重置演示清空数据；旧版本不认识 version 4，不能直接对含新快照的浏览器降级。若确需降级，应先保存快照并显式转换兼容副本，归档状态将无法由旧 UI 表达，须另行说明。
